# Automated Quality Assessment of LLM Generated Unit Tests: A Home Assistant Case Study

[![CI](https://github.com/rakeshreddy3466/llm-test-quality-assessment/actions/workflows/ci.yml/badge.svg)](https://github.com/rakeshreddy3466/llm-test-quality-assessment/actions/workflows/ci.yml)

Status: **work in progress** (see `PROGRESS.md`).

## Research questions
- **RQ1** How do LLM generated tests compare with developers' tests on executability, coverage,
  mutation score, traceability, maintainability (test smells), relevance and completeness?
- **RQ2** How well do automatic scores agree with a blinded manual review (Spearman rho, weighted kappa)?
- **RQ3** How sensitive are generated tests to metamorphic changes, compared with the noise between
  repeated samples?

### Key findings

- **Executability.** 15 of 15 LLM samples collect; 97.6 % of the 294 generated tests pass in all three runs (developer tests: 100.0 %); flaky rate 0.0 %.
- **Coverage and mutation (suite level).** Line coverage 100.0 % (developer) vs 99.6 % (union of the LLM samples); branch coverage 93.1 % vs 96.5 %; mutation score over the fixed 164 mutants 78.7 % vs 81.1 %.
- **Per target mutation score (global).** binary_sensor: 56.0 % per LLM sample vs 59.8 % for the developer file; config_flow: 5.4 % per LLM sample vs 47.6 % for the developer file; init: 50.0 % per LLM sample vs 54.3 % for the developer file.
- **Traceability.** Mean name-vs-coverage score 0.378 (developer) vs 0.301 (LLM); the LLM's declared `Target:` scores 0.533, and 92.0 % of valid LLM tests carry a parsable declaration.
- **Test smells.** Share of valid tests with at least one smell: 98.3 % (developer) vs 44.2 % (LLM); smell density 2.496 vs 0.662 per test.
- **Relevance and completeness (draft behaviour list).** Relevance 99.1 % (developer) vs 91.6 % (LLM); LLM completeness 100.0 % of the 38 behaviours reachable by the developer tests.
- **Metamorphic sensitivity.** pending (results/mr_metrics.csv missing).
- **Agreement with manual review (RQ2).** pending manual review.

## Setup
```bash
cp .env.example .env     # fill ANTHROPIC_API_KEY, HA_CORE_DIR, HA_PYTHON
uv sync
uv run testquality --help
uv run pytest
```
Requires Home Assistant core checked out at tag 2026.10.1 with its own `.venv`.

## Reproduce
```bash
# 1. environment: Home Assistant core at tag 2026.10.1 with its own .venv, and .env filled in
uv sync --extra analysis
uv run testquality generate --dry-run          # plan + cost estimate (no API call)
uv run testquality generate                    # k=5 samples x 3 targets (about 1 USD)
for s in developer main_sonnet55_v1; do        # replace by your run id
  uv run testquality execute --suite $s
  uv run testquality coverage --suite $s
  uv run testquality mutate --suite $s
  uv run testquality traceability --suite $s
  uv run testquality smells --suite $s
  uv run testquality relevance --suite $s
done
uv run testquality review-sample               # blinded manual-review sample
uv run testquality metamorphic --evaluate      # needs the variant runs (see docs/DECISIONS.md)
make all                                       # tables, figures, report and this section
```
The committed `data/runs/` and `results/*.csv` let you run `make all` without Home Assistant or an
API key. Design decisions: `docs/DECISIONS.md`; metric definitions: `docs/metrics.md`.
